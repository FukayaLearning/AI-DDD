# 試験計画

## 試験範囲

- **ケイパビリティ**: `ordering/order-management`（`REQ-ORD-001`..`REQ-ORD-004`、`SCN-ORD-001-01`..`SCN-ORD-004-01`）。
- **設計要素**: 値オブジェクト、`Order` 集約（カプセル化、生成/再構築、同一性、イベントライフサイクル、version）、マッパー、リポジトリ、在庫/決済ゲートウェイ、イベントパブリッシャ、ユースケース、Web UI。
- **対象外**: 本番用メッセージブローカー/outbox、分散マルチライター排他、新規ビジネス能力。

## 試験レベルと責務

- **単体（`UT-`）**: ドメイン不変条件、値オブジェクト検証、集約カプセル化、Factory 分離、同一性、イベントライフサイクル、マッパー、リポジトリ（version 競合）、ゲートウェイ、イベントパブリッシャ、ユースケース、Web UI 分岐。
- **結合（`IT-`）**: 実バイナリとファイル KV・HTTP スタブによるライフサイクル、不正入力、不正遷移、在庫/決済/タイムアウト/利用不可、永続化障害、未存在、複数明細、ローカライズ。

## 環境とテストダブル

- 単体テストはモック KV ドライバ、モック HTTP ドライバ、モックポート、記録用イベントパブリッシャを使う。
- 結合テストは構成可能な在庫/決済 HTTP スタブと一時データディレクトリを使う。
- 配布形態: 単体 Node.js プロセス（`binary`）。

## 開始・終了条件

- 開始: 計画成果物が完了し、schema v4 が適用されている。
- 終了: 全試験ケース合格、`ai-ddd trace --check` 合格、`infrastructure/drivers/` と `main` 以外の 100% C1 ブランチカバレッジ。

## 非機能試験

- 本参照実装では性能/セキュリティ/可用性試験は不要。結合テストでタイムアウトと補償を検証する。

- **廃止**: なし。
